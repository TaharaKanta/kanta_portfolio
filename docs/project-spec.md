# 投資ポートフォリオ・シミュレーター プロジェクト仕様（確定版 v1）

## 1. 概要

本プロジェクトは、株価・コモディティなどの市場データを取得し、ユーザーが設定したポートフォリオ配分に基づいて資産額の増減をシミュレーションできる Web アプリケーションです。

## 2. 目的

- ポートフォリオ案を事前に検証できるようにする。
- 配分比率の違いによるリターン・リスクの差を可視化する。
- 実運用前の意思決定を支援する。

## 3. 想定ユーザー

- ポートフォリオ設計を試したい個人投資家。
- 過去データで資産運用の挙動を学びたい初学者。

## 4. スコープ

### 4.1 MVP（初期版）

- 資産クラス対応: 株式、コモディティ、ETF、暗号資産、FX。
- 銘柄/商品/通貨ペアと配分比率の入力。
- ヒストリカルデータ取得と期間指定バックテスト。
- リバランス戦略の選択（少なくとも月次・四半期）。
- 手数料・税金を加味したシミュレーション設定。
- 基準通貨対応: JPY、USD、EUR。
- 資産推移グラフと基本指標（累積リターン、最大ドローダウン、ボラティリティ）表示。
- ログイン機能とポートフォリオ保存機能。

### 4.2 将来拡張

- 積立/取り崩しの定期シミュレーション。
- シナリオ分析（強気/中立/弱気）。
- 複数ポートフォリオの高度比較（ベンチマーク比較、期間差分比較）。
- 取引履歴を使った実績トラッキング。

## 5. 機能要件

1. データ取得

- 選択資産（株式、コモディティ、ETF、暗号資産、FX）の時系列データを取得できる。
- 通貨換算に必要な為替レートを取得できる。
- 休場日などの欠損データを一貫したルールで補正/スキップできる。

2. ポートフォリオ定義

- 資産の追加/削除ができる。
- 配分比率を入力できる。
- 合計 100% のバリデーションを行う。

3. シミュレーション実行

- 期間を指定できる。
- 日次でポートフォリオ評価額を算出できる。
- 手数料は固定手数料として設定できる。
- 税金は譲渡益課税・配当課税を対象として固定税率で設定できる。
- リバランスは月初実行とし、乖離しきい値は設けない。
- 基準通貨（JPY/USD/EUR）を選択できる。
- 主要指標を計算できる。

4. 可視化

- 資産推移の時系列チャート。
- 配分サマリー表示。
- パフォーマンス指標パネル表示。

5. 認証・保存

- ユーザーが OAuth でログインできる。
- ポートフォリオ設定とシミュレーション条件を保存/再利用できる。

## 6. 非機能要件

- レスポンシブ対応（PC/モバイル）。
- API エラー・レート制限時の明確なエラーハンドリング。
- 同一入力に対して再現可能な計算結果。
- API キーはサーバー側で安全に管理（クライアントへ露出しない）。
- ログイン情報と保存データを安全に取り扱う。

## 7. データソース方針（候補）

- 株式、コモディティ、ETF、暗号資産、FX を扱える API を採用。
- 選定基準:
  - 資産クラスの網羅性（株式/コモディティ/ETF/暗号資産/FX）。
  - ヒストリカルデータの品質・期間。
  - 料金とレート制限。
  - 利用規約の安定性（商用運用可否）。

## 8. 想定アーキテクチャ

- フロントエンド: Next.js（既存構成）
  - UI 設計は Container/Presentation パターンを採用する。
  - 役割定義と実装ルールは `docs/frontend-architecture.md` を参照する。
- サーバー層: Next.js Route Handler / Server Actions で API 取得・正規化
- 計算ロジック: TypeScript の独立モジュール化
- 認証基盤: OAuth（初期プロバイダーは実装時に確定）
- 永続化: ユーザー/ポートフォリオ/実行条件を保存する DB

## 9. MVP 指標定義（初期案）

- 累積リターン: 期間開始から終了までの増減率。
- 最大ドローダウン: 高値から安値までの最大下落率。
- ボラティリティ: 収益率の標準偏差（年率化ルールは要確定）。

## 10. マイルストーン

1. 要件確定とデータ API 選定。
2. 認証方式・DB スキーマの確定。
3. データ取得/正規化のプロトタイプ実装。
4. シミュレーションエンジン実装と単体テスト。
5. 可視化 UI 実装。
6. 保存機能実装。
7. サンプルポートフォリオで E2E 検証。

## 11. リスクと制約

- API レート制限により操作体験が悪化する可能性。
- 資産クラスごとのデータ品質差。
- 手数料、税金、配当、インフレ、為替換算の定義差による解釈ブレ。
- 複数資産クラスと複数通貨対応に伴う計算複雑化。

## 12. 決定事項（ユーザー回答反映）

1. MVP 対象資産に ETF、暗号資産、FX を含める。
2. MVP で固定手数料および税金（譲渡益 + 配当）を固定税率入力で計算できるようにする。
3. MVP でリバランスを必要機能として実装し、実行日は月初、乖離しきい値は使わない。
4. 基準通貨は JPY に加えて USD、EUR を対応対象とする。
5. MVP に OAuth ログイン機能とポートフォリオ保存機能を含める。

## 13. 実装確定事項（ユーザー回答反映）

1. 手数料モデル:

- 固定手数料を採用する。

2. 税金モデル:

- 譲渡益課税に加え、配当課税も対象に含める。
- 税率は固定入力方式を採用する。

3. リバランス実行ルール:

- 実行日は月初を採用する。
- 乖離しきい値は使用しない（定期実行のみ）。

4. マルチ通貨換算:

- 評価額換算は日次終値換算を採用する。
- 為替データ欠損時の補完ルールは前営業日引き継ぎとする。

5. 認証方式:

- 初期対応は OAuth を採用する（プロバイダーは実装時に確定）。
